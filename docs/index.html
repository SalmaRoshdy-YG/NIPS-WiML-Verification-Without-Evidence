When Is a Multi-Agent Code Judge Actually Grounded?

Two label-free measurements, and a judge that declines to guess

The idea

Teams now let one language model write code and a second one decide whether it can merge. When the second model has no basis for a decision, it does not say so. It returns a confident verdict that looks the same as one it had good reason for.

One promising fix is to stop asking a single model for a verdict. Break the judgment into small checkable claims and have a separate agent verify each claim, kept away from the first model's reasoning. We ask what this needs in order to work, and whether we can check that before relying on it.

Two conditions for grounding

IndependentThe evidence must not come from the answer under review, or the checker just re-reads it and agrees.
Differs between candidatesEvidence identical for both solutions is reliable, yet tells you nothing. With retrieved documents this holds automatically. In code judging it stops holding.

The method

We ran a published framework, MARCH, unmodified as a pairwise code judge on CodeJudgeBench: two solutions to the same problem, one correct and one subtly buggy, and the judge picks the correct one.

  1. SolverReads the problem and a solution and forms an opinion on whether it is correct.
  2. ProposerTurns that opinion into a list of individually checkable claims.
  3. Our gateIf the proposer asked the same questions about both solutions, withhold the comparison. Needs no labels and no extra model calls.
  4. CheckerAnswers each claim from the problem and solution, without seeing the solver's reasoning.
  5. VerdictThe solution that survives more of its claims wins. Equal scores are a tie.

Data: CodeJudgeBench (generators Gemini-2.5-Pro, Claude-3.7-Sonnet and Qwen3-235B, three difficulty levels) and HumanEvalFix. Judges: Qwen3-8B and Qwen3-14B. 54 experimental cells, about 2,000 comparisons.

The results

The pipeline never errors, yet it has nothing to go on. Two measurements, both computed from logs it already writes and with no ground-truth labels, explain why.

Accuracy reaches 4.4% where the same model asked directly reaches 43.7% (p = 1.1×10−20). Easier problems do not help the pipeline, and neither does a 1.75× larger judge.

The repair: decline to guess

Withholding comparisons where the questions are identical raises accuracy from 20.7% to 36.9% while still answering about half (50.6%) of them. The gain holds in every generator and difficulty level, under both judges. It does not make the pipeline competitive with the single model it is built from, which answers every comparison and is right on 73.4% of them.

Takeaways

  • A verifier needs evidence that is independent and that differs between the candidates.
  • Both properties can be measured from logs the pipeline already writes, with no labels.
  • Gating is a partial repair, not a solution: the direct judge still wins.
  • The contribution is knowing when a judge has no basis for its answer, and declining to guess.
